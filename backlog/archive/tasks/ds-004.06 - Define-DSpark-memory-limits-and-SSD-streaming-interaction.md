## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Make memory planning and option compatibility explicit for preserved-MXFP4 DSpark bundles, especially on 128 GB Apple Silicon. Avoid downloading or mapping an optional support model when the requested runtime configuration is impossible.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Startup reports receiver, support model, KV, buffers, cache/repack, and peak temporary allocations separately in bytes and GiB.
- [ ] #2 Headroom128 and Quality128 bundle plans fit their documented 128 GB safety targets under validated context and generation settings.
- [ ] #3 --ssd-streaming with --mtp/--dspark remains an early actionable error until an implementation and validation task explicitly removes the limitation.
- [ ] #4 Incompatible option detection occurs before HF support-artifact download and before either model is mapped.
- [ ] #5 OOM planning fails before unsafe allocation with calculated required/available memory and suggested target-only or smaller-context alternatives.
- [ ] #6 Unload/reload and failed-start paths restore unified memory and do not retain support-model caches.
- [ ] #7 Measured process-tree peaks are recorded for both product profiles on the 128 GB M1 Ultra.
