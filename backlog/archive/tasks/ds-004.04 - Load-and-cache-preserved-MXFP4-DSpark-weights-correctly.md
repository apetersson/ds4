## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Extend support-model loading, model-view ownership, Metal cache preparation, and tensor dispatch so preserved MXFP4 DSpark weights coexist with the primary receiver without type confusion, eviction of required target spans, or excessive duplicate residency.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The loader accepts verified preserved-MXFP4 support tensors and rejects incompatible type/shape combinations before GPU execution.
- [ ] #2 Primary and support model maps retain distinct ownership and cache keys even when tensor names or offsets have analogous roles.
- [ ] #3 MXFP4 support tensors use the correct packed Metal path and never enter IQ2/Q4-only repack logic.
- [ ] #4 Cache preparation cannot evict or overwrite receiver mappings required for target verification.
- [ ] #5 Single-GPU/Metal memory planning accounts separately for receiver, support model, KV, buffers, repack/cache, and temporary verification state.
- [ ] #6 Startup failure releases both model maps and GPU resources without leaving the process lock or stale cache state.
- [ ] #7 Existing non-preserved DSpark support GGUFs retain loader compatibility.
<!-- AC:END -->
