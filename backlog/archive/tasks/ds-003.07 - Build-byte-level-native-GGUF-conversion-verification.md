## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Provide an independent verifier that compares the final GGUF against source shards and the frozen inventory. Verification must detect semantic substitutions that a simple file checksum or tensor histogram would miss and emit a durable machine-readable report.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The verifier checks GGUF structure, metadata, tensor names, shapes, types, offsets, alignment, payload sizes, and complete file coverage.
- [ ] #2 F16/F32/I32 tensors are compared exactly after the declared representation mapping.
- [ ] #3 MXFP4 packed values and scales are decoded or byte-mapped independently enough to detect nibble order, block order, scale, stride, and truncation errors.
- [ ] #4 The report includes source revision/hashes, converter revision, output SHA-256/bytes, tensor histogram, per-class verification counts, failures, and elapsed resources.
- [ ] #5 Verification failure returns nonzero and cannot leave a report marked passed.
- [ ] #6 Known-corruption fixtures prove detection of one-bit payload changes, swapped blocks, wrong dtype metadata, wrong tensor offsets, and missing tensors.
- [ ] #7 The production native GGUF report is stored alongside catalog provenance and reproducible from documented commands.
<!-- AC:END -->
