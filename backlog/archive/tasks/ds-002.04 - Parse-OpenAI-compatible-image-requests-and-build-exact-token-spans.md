## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Accept the supported OpenAI chat image_url content shape, preserve text ordering, create the exact DeepSeek image-token scaffold, and associate one encoder result with the correct request. Unsupported multimodal combinations must fail explicitly rather than degrade into text or hallucinated image descriptions.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 /v1/chat/completions accepts one documented image_url content part using data:, http:, https:, file:, or server-local path forms allowed by server policy.
- [ ] #2 The image placeholder expands to exactly the route tokens and 257, 769, or 1281 image-token positions declared by the encoder result.
- [ ] #3 Text before and after the image retains client order and the generated prompt matches golden tokenization fixtures.
- [ ] #4 Missing image data, multiple images, multiple user image turns, unsupported MIME data, malformed content arrays, and layout/context overflow return structured 4xx errors.
- [ ] #5 The request cannot silently proceed as text-only when image encoding or span construction fails.
- [ ] #6 Streaming and non-streaming responses share the same validated multimodal prefill path.
- [ ] #7 Text-only OpenAI, Responses, Anthropic, and completion endpoints retain existing behavior.
<!-- AC:END -->
