## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Define a versioned, declarative DS4 catalog manifest based on the existing variants.json layout. The parser must expose typed receiver and optional companion artifacts without treating Transformers config.json as executable runtime configuration. The schema must remain useful for ordinary text GGUF repositories and allow later vision extensions.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Schema version, repository metadata, default selector, variant selector, receiver path, byte count, SHA-256, quant/profile labels, and optional typed companion records are defined.
- [ ] #2 Unknown optional fields are ignored while unknown required capabilities and unsupported major schema versions fail with actionable errors.
- [ ] #3 Duplicate selectors, empty paths, absolute paths, path traversal, malformed SHA-256 values, impossible sizes, and conflicting defaults are rejected.
- [ ] #4 The manifest parser has explicit size, nesting, string-length, variant-count, and artifact-count limits.
- [ ] #5 Manifest values cannot inject command-line arguments, environment variables, executable paths, shell fragments, or remote code.
- [ ] #6 Parser tests include the production Headroom128 and Quality128 catalog shapes plus malformed and adversarial fixtures.
<!-- AC:END -->
