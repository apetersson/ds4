## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Define variants.json schema v2 as DS4's typed integrity and capability manifest. It must describe a shared ordinary DeepSeek4 receiver, DS4-native vision components, a llama.cpp mmproj companion, and optional DSpark, while acknowledging that llama.cpp selects solely from repository paths, filenames, and GGUF metadata.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Schema defines repository/default selector plus per-variant receiver, ds4_vision, llama_cpp_mmproj, and optional dspark records with paths, byte counts, SHA-256, precision, profile, required/optional capability, and minimum runtime revision.
- [ ] #2 Shared vision metadata records image token/id, 1024 image size, 896-to-4096 projection, 256 rows per view, one separator, preprocessing contract, and token formula views*256+1 rather than the incomplete layouts enumeration.
- [ ] #3 Schema and fixtures account for 257, 769, 1025, and 1281-row cases and reject an implementation that assumes only the previous 257/769/1281 set.
- [ ] #4 Unknown optional fields are ignored while unknown required capabilities and unsupported major versions fail actionably.
- [ ] #5 Duplicate selectors, unsafe paths, malformed hashes/sizes, conflicting defaults, incomplete companion bundles, and mismatched runtime capability declarations are rejected within explicit parser resource limits.
- [ ] #6 Manifest data cannot inject argv, environment, executable paths, shell fragments, or remote code; the encoder executable/interpreter remains trusted local configuration.
- [ ] #7 Production Headroom128 and Quality128 fixtures prove that main/mmproj/dspark filenames also satisfy llama.cpp sibling discovery independently of the manifest.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Define bounded v2 manifest data structures and a non-executable JSON parser; validate typed artifacts, capabilities, runtime constraints, vision metadata, row formula, duplicate/default/path/hash/size/bundle invariants, and independent llama.cpp sibling naming. Add production-shaped Headroom128 and Quality128 fixtures with focused positive and negative tests, then run relevant non-model gates and fresh parent-scoped iterative reviews.
