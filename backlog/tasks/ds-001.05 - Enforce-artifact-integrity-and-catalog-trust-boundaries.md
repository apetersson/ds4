## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Validate every selected receiver or companion before DS4 opens it. Enforce a data-only trust boundary while supporting runtime-specific representations of the same lossless BF16 vision weights.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Every downloaded receiver, tower, projector, config, and requested DSpark artifact is checked against manifest byte count and SHA-256 before loading.
- [x] #2 The catalog records and tests source-to-mmproj BF16 tensor identity separately; DS4 does not infer mmproj trust from matching names or shared HF LFS objects.
- [x] #3 Cached mismatch fails closed with a non-destructive recovery command and never falls back to a same-directory heuristic artifact.
- [x] #4 Path traversal, symlink escape, special files, snapshot escape, replacement races, and manifest mutation are rejected.
- [x] #5 No Python module, auto_map entry, shell command, encoder script, or executable downloaded from the model repository is automatically run.
- [x] #6 Integrity tests cover valid, truncated, same-size corrupt, cross-variant substituted, mmproj-vs-raw-role-confused, symlink, and concurrent replacement cases.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Extend the bounded catalog with an explicit canonical BF16 tensor-identity record that independently binds raw DS4 vision sources to the llama.cpp mmproj representation.
2. Add SHA-256 verification and descriptor-anchored, no-follow cache operations so every requested role is revalidated and path/symlink/special-file/snapshot/replacement failures fail closed with an explicit non-destructive recovery command.
3. Add deterministic integrity coverage for all acceptance-criterion corruption and race cases while preserving the data-only/no-execution boundary and leaving binary wiring/dry-run UX to DS-001.06/DS-001.08.
4. Run focused integrity, existing HF, strict/sanitizer, CPU/native, and established safe non-model gates; commit stable changes, then repeat fresh read-only parent-scope reviews with tracked Include-now findings until exact ALL GOOD.
