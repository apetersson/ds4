## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Define the repository workflow that keeps upstream-tracking main clean, develops each concern in its own worktree, and uses integration/dev for planned integration-owned artifacts plus explicit feature merges. Prevent accidental reverse merges from integration/dev into upstreamable feature branches.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 main is documented and mechanically checked as fast-forward-only from upstream/main with no fork-only commits.
- [ ] #2 Each feature branch and absolute worktree path is recorded, including ownership of HF, vision, native GGUF, and DSpark scopes.
- [ ] #3 Feature branches receive changes from main or their declared base only; integration/dev is never merged or rebased back into them.
- [ ] #4 Integration-owned commits are limited to Backlog, merge policy, catalog fixtures, cross-feature tests, release reports, and documentation.
- [ ] #5 A script or documented command reports branch base, divergence, uncommitted files, merge ancestry, and accidental cross-feature commits.
- [ ] #6 Existing composite feature/vision-embedding-span and old fix branches remain preserved as migration references until clean branches validate.
- [ ] #7 Worktree creation, pruning, and removal commands use explicit paths and refuse dirty worktrees.
<!-- AC:END -->
