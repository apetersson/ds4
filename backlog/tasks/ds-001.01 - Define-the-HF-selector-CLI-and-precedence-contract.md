## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Define the user-visible repository/selector and companion-control contract for ds4 and ds4-server. Match established llama.cpp spellings where semantics are shared, while retaining DS4-specific local vision component options.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Both binaries accept -hf, -hfr, --hf-repo, and --hf as aliases for OWNER/REPO[:SELECTOR]; selector matching is case-insensitive and exact-file selection is available through -hff/--hf-file.
- [x] #2 HF_TOKEN is the default credential source; -hft/--hf-token, HF_ENDPOINT, --hf-revision, --hf-cache-dir, and --offline/--hf-offline have unambiguous non-leaking semantics.
- [x] #3 --model and HF receiver selection are mutually exclusive and fail before model allocation.
- [x] #4 With ds4-server and -hf, vision auto-discovery is enabled by default when the variant declares a complete DS4 vision bundle; --no-vision disables it without downloading vision files.
- [x] #5 An explicit complete set of --vision-python/--vision-encoder/--vision-tower/--vision-adapter overrides catalog vision; partial explicit/catalog mixing is rejected unless every role and precedence rule is deterministic.
- [x] #6 Explicit --mtp retains precedence over manifest DSpark; --dspark remains explicit opt-in and cannot silently alter target-only behavior.
- [x] #7 CLI tests cover official llama.cpp-style examples, malformed selectors, aliases, duplicate flags, missing arguments, explicit overrides, --no-vision, and incompatible options.
<!-- AC:END -->
