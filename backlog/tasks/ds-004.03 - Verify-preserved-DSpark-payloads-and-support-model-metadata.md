## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Validate that the generated support GGUF contains the intended preserved packed payloads, required MTP/DSpark tensor set, and metadata needed to bind it to the correct receiver family and runtime. Prevent an auxiliary GGUF from being mistaken for a standalone receiver.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Preserved MXFP4 tensor values/scales compare exactly to source according to the declared packed mapping.
- [ ] #2 The support GGUF includes every required DSpark tensor exactly once with expected name, shape, type, and byte count.
- [ ] #3 Metadata identifies the file as an auxiliary DSpark/MTP support model, its architecture/family, conversion provenance, and compatible receiver contract.
- [ ] #4 A support GGUF cannot pass verification when required tensors are missing, extra receiver-only tensors are present, or compatibility metadata conflicts.
- [ ] #5 The verifier emits output SHA-256, size, type histogram, preserved count/bytes, receiver-compatibility fields, and pass/fail status.
- [ ] #6 Catalog/HF documentation can distinguish the file from an independently runnable quant based on metadata and manifest role.
<!-- AC:END -->
