## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Acquire only the manifest-selected receiver and requested typed companions through the official Hugging Face download/cache behavior. Downloads occur during server startup, not in the token generation path, and must recover safely from interruption and concurrent launches.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Selecting Headroom128 does not download Quality128, native reference, MLX, evaluation, or unrelated GGUF artifacts.
- [ ] #2 The implementation uses an existing hf CLI when required for Xet-backed large files and reports a precise installation requirement when no safe transport is available.
- [ ] #3 Partial files are resumable and are never exposed to the model loader as complete artifacts.
- [ ] #4 Concurrent processes resolving the same revision cannot corrupt the cache or observe a half-published file.
- [ ] #5 A successful second launch reuses the cache without retransferring unchanged artifacts.
- [ ] #6 Cache location follows --hf-cache-dir and documented environment/default behavior and supports paths containing spaces.
- [ ] #7 Download errors report repository, immutable revision, artifact role, expected size, and cache destination without leaking credentials.
<!-- AC:END -->
