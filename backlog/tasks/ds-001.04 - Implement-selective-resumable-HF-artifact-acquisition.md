## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Acquire only the selected receiver and runtime-requested companions. DS4 server vision uses tower/projector/config assets; llama.cpp consumes its separate mmproj GGUF. The resolver must never download both representations merely because both are cataloged.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Selecting Headroom128 never downloads Quality128, native reference, MLX, evaluations, or unrelated variants.
- [ ] #2 ds4 text-only or --no-vision downloads only receiver files; ds4-server auto-vision downloads only receiver plus ds4_vision roles; --dspark adds only the matching DSpark role.
- [ ] #3 The sibling llama_cpp_mmproj path is exposed by listing/dry-run metadata but is not downloaded by DS4 unless an explicit catalog-materialization operation requests it.
- [ ] #4 Transport supports HF LFS/Xet through a safe available client, resumes interruption, never publishes partial files, and reports precise prerequisites.
- [ ] #5 Concurrent resolution cannot corrupt the cache; a successful second launch reuses unchanged verified files.
- [ ] #6 Cache location follows CLI/environment/default semantics, supports spaces, and records immutable repository revision and artifact role.
- [ ] #7 Errors include repository, revision, selector, role, expected size, and destination without leaking credentials.
<!-- AC:END -->
