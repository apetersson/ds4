## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Allow a selected catalog variant to declare its matching DSpark/MTP support GGUF. Discovery is automatic, but activation remains explicit through --dspark so target-only behavior, memory use, sampling, and SSD-streaming compatibility do not change silently.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 --hf REPO:SELECTOR --dspark resolves the declared DSpark artifact and supplies it to the existing MTP runtime without requiring --mtp PATH.
- [ ] #2 --hf REPO:SELECTOR without --dspark neither downloads nor maps the DSpark artifact.
- [ ] #3 --dspark fails before receiver allocation when the selected variant has no DSpark companion.
- [ ] #4 An explicit --mtp PATH has documented precedence and cannot silently combine with a different manifest-declared support model.
- [ ] #5 Existing DSpark confidence, strict, exact-sampling, draft-token, and margin options continue to work with a discovered companion.
- [ ] #6 The existing --ssd-streaming and --mtp incompatibility is detected before downloading an optional DSpark artifact.
- [ ] #7 Tests demonstrate target-only parity and successful discovered-sidecar startup using small fixture GGUF metadata.
<!-- AC:END -->
