## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Provide llama.cpp-familiar offline/cache behavior and machine-readable planning for very large runtime-specific bundles. Diagnostics must distinguish DS4 raw vision components from llama.cpp mmproj and must not add both to one runtime total.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 --list-hf-variants fetches only metadata and prints selector, receiver, DS4 vision, llama mmproj, DSpark, precision, runtime compatibility, and declared capabilities.
- [ ] #2 --hf-dry-run reports immutable revision, exact selected files, cached/missing state, per-role bytes, transfer total, and selected runtime weight total without model load.
- [ ] #3 --offline and --hf-offline perform no DNS/network and succeed only from a complete verified snapshot for requested roles.
- [ ] #4 Dry-run distinguishes receiver-only, DS4 receiver+vision, DS4 receiver+vision+DSpark, and llama.cpp receiver+mmproj catalog totals.
- [ ] #5 Diagnostics report both manifest-directed selection and whether the same layout passes llama.cpp filename/sibling heuristics.
- [ ] #6 Stable JSON and human output have golden tests and never classify mmproj/DSpark GGUFs as receiver variants.
