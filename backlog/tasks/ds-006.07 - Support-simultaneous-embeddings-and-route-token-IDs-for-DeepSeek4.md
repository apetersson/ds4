## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Extend libllama's batch/input plumbing so visual embeddings can coexist with semantic token IDs needed by DeepSeek4 ffn_gate_tid2eid. Embeddings supply hidden states; token IDs remain available only to architecture-specific token-conditioned graph inputs.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 llama_batch, allocator/free path, validation, ubatch splitting, graph inputs, and mtmd helper preserve both embd and token arrays when both are supplied.
- [ ] #2 Existing token-only and embedding-only API behavior, ABI expectations, batching, sequence positions, KV reuse, and error handling remain compatible.
- [ ] #3 DeepSeek4 uses token ID 129279 for ffn_gate_tid2eid on every visual embedding row including the separator, while input hidden states come from mmproj embeddings.
- [ ] #4 Architectures without token-conditioned routing ignore the auxiliary IDs and retain byte-identical deterministic text/embedding behavior.
- [ ] #5 Tests cover mixed batches, split ubatches, continuous batching, multiple sequences, KV reuse, invalid combinations, and all four visual-row layouts.
- [ ] #6 DeepSeek4 text-only logits are unchanged; a negative test proves missing/wrong route IDs diverge from the validated visual receiver oracle.
