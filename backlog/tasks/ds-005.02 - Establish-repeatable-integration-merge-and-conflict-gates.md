## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Define and exercise the ordered merge of completed feature branches into integration/dev. Resolve shared-file conflicts deliberately, retain upstreamable feature histories, and prove that the merged code compiles and passes baseline tests after every feature merge.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Merge order and rationale are documented, including shared hotspots such as ds4.c, ds4_server.c, ds4_metal.m, Makefile, tests, and README.
- [ ] #2 Each feature merge uses a visible merge commit and records source branch tip, base revision, conflicts, resolution owner, and validation result.
- [ ] #3 Conflict resolutions are integration-only unless they reveal a feature-branch defect, in which case the fix lands in the owning feature branch and is remerged.
- [ ] #4 After each merge, required CPU build/tests run; Metal/server/HF/vision/DSpark gates run as soon as their dependencies are present.
- [ ] #5 A clean rebuild from integration/dev succeeds without files borrowed from the old composite checkout.
- [ ] #6 Branch topology checks prove no feature branch contains integration-only merge commits.
- [ ] #7 Failed merges or validation leave a recoverable worktree and do not rewrite feature branch history.
<!-- AC:END -->
