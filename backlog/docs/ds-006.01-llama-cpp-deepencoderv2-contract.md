## 2. Frozen upstream download and two-GGUF behavior

The current architecture is two independent GGUFs. The primary GGUF is loaded by
libllama; the `mmproj` GGUF is loaded by libmtmd, which owns media decoding,
preprocessing, the vision graph, and the production of rows in the language
model's embedding width. See
[`tools/mtmd/README.md`](https://github.com/ggml-org/llama.cpp/blob/d222767c7a6516559a3f49e7721b6c6b1acc87b4/tools/mtmd/README.md)
and
[`docs/multimodal.md`](https://github.com/ggml-org/llama.cpp/blob/d222767c7a6516559a3f49e7721b6c6b1acc87b4/docs/multimodal.md).
DSpark is a speculative-decoding sidecar and is neither the primary model nor
the mmproj.

The following is the exact behavior of
[`common/download.cpp`](https://github.com/ggml-org/llama.cpp/blob/d222767c7a6516559a3f49e7721b6c6b1acc87b4/common/download.cpp)
and
[`common/arg.cpp`](https://github.com/ggml-org/llama.cpp/blob/d222767c7a6516559a3f49e7721b6c6b1acc87b4/common/arg.cpp)
at the pin.

### 2.1 Primary selection

1. A root-level path exactly equal to `preset.ini` preempts GGUF planning and
   returns a preset-only plan.
2. `-hff FILE` / `--hf-file FILE` selects an exact, case-sensitive repository
   path and overrides the `:quant` selector in `-hf`. This branch bypasses model
   eligibility, lowercase `.gguf`, sidecar exclusion, and split-index-1 checks;
   even a non-GGUF or later split is accepted if its path is exact.
3. Otherwise, an explicit `-hf repo:tag` searches eligible model paths in
   repository enumeration order using the case-insensitive regex `tag + "[.-]"`.
   The selector is not regex-escaped. A requested tag that has no match is a hard
   miss; it does not fall back.
4. With no tag, selection tries `Q4_K_M`, then `Q8_0`, case-insensitively, then
   the first eligible model in repository enumeration order.
5. Only split index 1 may be selected as primary. Its other parts are collected
   by the same parsed integer split count and a byte-for-byte, case-sensitive
   prefix. The split regex is case-insensitive, but `.gguf` suffix removal and
   subsequent prefix equality are case-sensitive.
6. Eligibility requires a lowercase `.gguf` suffix and excludes a basename
   containing lowercase `mmproj`, `imatrix`, `mtp-`, `eagle3-`, `dflash-`, or
   `dspark-`. These exclusions are case-sensitive; for example, `MMPROJ-X.gguf`
   can be misclassified as a primary.

### 2.2 mmproj and DSpark sibling selection

Sibling candidates require an exact lowercase `.gguf` suffix and a
case-sensitive path substring:

| Sidecar | Required substring | Enabled by |
| --- | --- | --- |
| mmproj | `mmproj` | an mmproj-capable example, auto enabled, no explicit mmproj path/URL, and a selected primary |
| DSpark | `dspark-` | speculative type `draft-dspark`; may resolve without a primary |

The same generic sibling scorer is used for `mtp-`, `dflash-`, and `eagle3-`.
For every candidate it applies this ordering:

1. Split both paths on `/`, ignore each basename, and require every sibling
   directory component to equal the corresponding leading primary directory
   component. Therefore the sibling may be in the primary's exact directory or
   any ancestor, including repository root; divergent directories and deeper
   child directories are rejected.
2. Prefer the greatest sibling directory depth. An exact-directory sidecar wins
   over an ancestor fallback.
3. If a nonempty `:tag` was requested, uppercase candidate and tag and prefer a
   path containing exact `-TAG.`. This exact test is case-insensitive but still
   punctuation-specific.
4. Prefer the smallest absolute quant-bit difference. The target is the first
   decimal number in the requested tag, or otherwise in the primary's derived
   uppercase final tag. A tag without digits contributes 0 bits.
5. A complete tie keeps the first repository-enumerated candidate.

The final filename tag and split regexes are case-insensitive and the derived tag
is uppercased, but `.gguf`, split-prefix equality, and the sidecar keywords remain
case-sensitive. No general basename equality or same-tag requirement exists.
mmproj scoring has no explicit requested tag argument, so it quant-matches the
selected primary; DSpark scoring receives the requested `:tag` when present. If
a requested sidecar resolves without a primary, the empty model directory makes
only repository-root sidecars eligible; a nested draft-only DSpark is rejected.
Sidecar selection neither requires split index 1 nor expands sidecar splits, so
DS-006 packages each mmproj/DSpark sidecar as one file.

### 2.3 Controls and precedence

| Concern | CLI/environment | Frozen effect |
| --- | --- | --- |
| Primary HF repo | `-hf`, `-hfr`, `--hf-repo`; `LLAMA_ARG_HF_REPO` | Repo plus optional `:tag` |
| Exact primary | `-hff`, `--hf-file`; `LLAMA_ARG_HF_FILE` | Exact case-sensitive path, overrides tag |
| Authentication | `-hft`, `--hf-token`; `HF_TOKEN` | Bearer token only; no scoring effect |
| Offline | `--offline`; `LLAMA_ARG_OFFLINE` | Use cached repository listing/files only |
| Explicit mmproj | `-mm`, `--mmproj`; `LLAMA_ARG_MMPROJ` | Prevents automatic mmproj sibling planning |
| Explicit mmproj URL | `-mmu`, `--mmproj-url`; `LLAMA_ARG_MMPROJ_URL` | Prevents automatic mmproj sibling planning |
| mmproj discovery | `--mmproj-auto` / `--no-mmproj`, `--no-mmproj-auto`; `LLAMA_ARG_MMPROJ_AUTO`, synthesized `LLAMA_ARG_NO_MMPROJ_AUTO` | Enable/disable automatic sidecar use; flags are registered only for mtmd, server, CLI, and download |
| mmproj offload | `--mmproj-offload`, `--no-mmproj-offload`; `LLAMA_ARG_MMPROJ_OFFLOAD`, synthesized `LLAMA_ARG_NO_MMPROJ_OFFLOAD` | Backend offload only, not discovery; registered for mtmd, server, CLI, and TTS |
| mmproj device | `-mmdev`, `--mmproj-device`; `MTMD_BACKEND_DEVICE` | Select one backend device, or `none`; not discovery |
| Draft repo | `--spec-draft-hf`, `-hfd`, `-hfrd`, `--hf-repo-draft`; `LLAMA_ARG_SPEC_DRAFT_HF_REPO` | Separate HF plan for speculative model/sidecars |
| Exact draft file | `--spec-draft-model`, `-md`, `--model-draft`; `LLAMA_ARG_SPEC_DRAFT_MODEL` | Also becomes draft `hf_file`; disables draft-repo sidecar resolution |
| Sidecar type | `--spec-type draft-dspark`; `LLAMA_ARG_SPEC_TYPE` | Requests DSpark discovery; the default `none` does not request main-repo DSpark |

Automatic mmproj discovery is active for the `mmproj_examples` set: mtmd,
server, CLI, and TTS, and it requires a selected primary. The auto/disable flags
are registered for mtmd, server, CLI, and download, however, so TTS cannot parse
`--mmproj-auto`, `--no-mmproj`, or `--no-mmproj-auto` at this pin. In mtmd,
server, and CLI, `--no-mmproj` disables discovery. In TTS, supplying `-mm` or
`-mmu` is the only parser-supported way to suppress automatic sibling selection;
the explicitly supplied projector is still used. The download example accepts
the auto/disable control but is not in `mmproj_examples`, so it does not request
an mmproj download through `common_models_handler_init`. An explicitly supplied
mmproj path or URL always prevents automatic sibling planning. `common_arg`
synthesizes the two `LLAMA_ARG_NO_*` compatibility aliases above from the
negative option forms.

When a draft repo is supplied and speculative type remains default, llama.cpp
discovers all four draft-sidecar kinds and infers one in this order:
`mtp` > `dspark` > `dflash` > `eagle3`; DSpark outranks DFlash because it carries
the extra Markov head. A draft URL/path already wired by the caller prevents a
discovered sidecar from replacing it. A sidecar resolved from the draft repo also
prevents fallback to a sidecar from the primary repo. With an explicitly
requested sidecar type, only that type is planned. A sharded draft's metadata
cannot safely infer the type; pass `--spec-type` explicitly.

Packaging under DS-006.08 must therefore use lowercase `.gguf`, `mmproj`, and
`dspark-`, place sidecars in the same variant directory as the primary whenever
possible, and test `-hf repo:tag` as well as `-hff` overrides. Casing that merely
looks equivalent is not compatible at this pin. Source-level resolver fixtures
must also prove that `-hff` bypasses eligibility and split-index filtering, and
that primary-less sidecars resolve at repository root but not below it.

DeepSeek-OCR-2 cannot be used directly because it has a different image
preprocessor, a single `mm_fc` projection rather than the donor's two-layer GELU
projector, and separator placement after only its global branch rather than once
after all flattened views. It also has no DeepSeek4 raw-route-token bridge.

The lossless converter also cannot inherit current base dtype policy unchanged.
`ModelBase.prepare_tensors` forces every one-dimensional tensor, every
`*_norm.weight`, and every tensor name without a weight/LoRA suffix to F32;
`MmprojModel.tensor_force_quant` separately forces patch embeddings to F32 unless
the file is F16. These paths would routinely promote donor BF16 norms, biases,
separator, queries/positions, and patch weights.

DS-006.02 must add a default-off `ModelBase` hook named
`tensor_preserve_source_dtype(name, new_name, bid, n_dims)`. When the dedicated
DeepEncoderV2 converter returns true for its exact 475-tensor output allowlist,
`prepare_tensors` must first assert source dtype BF16 and selected file type
`MOSTLY_BF16`, choose BF16 directly, and bypass `tensor_force_quant` plus every
generic F32 coercion. All other converters take the unchanged false branch. Tests
must include 1-D norms/biases/separator, positional/relative tensors, and the
patch embedding so the hook cannot accidentally preserve unrelated tensors.

## 4. Canonical DeepEncoderV2 contract

### 4.1 Metadata registry

The converter must emit a vision-only mmproj GGUF and the loader must fail closed
on missing or contradictory values. Existing standard keys remain authoritative:

| GGUF key | Type/value | Meaning |
| --- | --- | --- |
| `general.architecture` | string `clip` | Existing mmproj architecture |
| `clip.has_vision_encoder` | bool `true` | Vision encoder present |
| `clip.projector_type` | string `deepencoder_v2_dsv4` | New discriminator; do not overload `deepseekocr2` |
| `clip.vision.image_size` | u32 `1024` | Square input per view |
| `clip.vision.patch_size` | u32 `16` | SAM patch size |
| `clip.vision.image_mean` | f32 array `[0.5, 0.5, 0.5]` | RGB normalization |
| `clip.vision.image_std` | f32 array `[0.5, 0.5, 0.5]` | RGB normalization |
| `clip.vision.embedding_length` | u32 `896` | Qwen and SAM-neck output width |
| `clip.vision.projection_dim` | u32 `4096` | DeepSeek4 receiver width |
| `clip.vision.block_count` | u32 `24` | Qwen layers |
| `clip.vision.feed_forward_length` | u32 `4864` | Qwen gated FFN width |
| `clip.vision.attention.head_count` | u32 `14` | Q heads, head width 64 |
| `clip.vision.attention.head_count_kv` | u32 `2` | GQA KV heads |
| `clip.vision.attention.head_dim` | u32 `64` | Existing optional key; must equal `896 / 14` |
| `clip.vision.attention.layer_norm_epsilon` | f32 `1e-6` | Qwen RMS norm epsilon |
| `clip.vision.sam.block_count` | u32 `12` | SAM depth |
| `clip.vision.sam.embedding_length` | u32 `768` | SAM transformer width |
| `clip.vision.sam.head_count` | u32 `12` | SAM attention heads |
| `clip.vision.window_size` | u32 `14` | SAM local attention window |

Do not emit either `clip.use_gelu` or `clip.use_silu`. At this pin both select one
graph-wide `hparams.ffn_op`: `clip.use_gelu` means approximate `FFN_GELU`, while
`clip.use_silu` would incorrectly make reused SAM blocks use SiLU. The dedicated
DeepEncoderV2 graph must specialize each stage explicitly: SAM uses
`FFN_GELU_ERF`, Qwen uses `FFN_SILU`, and the projector uses `FFN_GELU_ERF`.
Those are the ggml equivalents of the donor's exact PyTorch GELU and Qwen SiLU;
the graph must not consult the global `hparams.ffn_op` for any of these stages.

The following new keys freeze donor-only behavior. They belong in the upstream
GGUF registry/writer rather than as unregistered string literals:

| GGUF key | Type/value |
| --- | --- |
| `clip.deepencoder_v2.image_token_id` | u32 `129279` |
| `clip.deepencoder_v2.image_token` | string `<｜image｜>` |
| `clip.deepencoder_v2.tokens_per_view` | u32 `256` |
| `clip.deepencoder_v2.tiles` | u32 `2` |
| `clip.deepencoder_v2.tile_threshold` | f32 `1.5` |
| `clip.deepencoder_v2.separator_tokens` | u32 `1` |

| `clip.deepencoder_v2.separator_position` | string `last` |
| `clip.deepencoder_v2.projector_activation` | string `gelu_exact` |

The Qwen constants fixed by the donor graph but not represented by dedicated

remain explicit in the DeepEncoderV2 graph and are not user-tunable at this
compatibility version.

### 4.3 Pixels, views, rows, and separator

For input width `w`, height `h`, and checkpoint `tiles`:

```text
tile if tiles > 1 and max(w, h) >= 1.5 * 1024
max_grid_tiles = tiles * tiles
candidate grids = (cols, rows), 1 <= cols,rows <= max_grid_tiles,
                  cols*rows <= max_grid_tiles, cols*rows != 1
score = (abs(cols/rows - w/h), -(cols*rows))
grid = lexicographic minimum score
crop(c,r) = (c*w//cols, r*h//rows, (c+1)*w//cols, (r+1)*h//rows)
views = [global image] + crops with rows outer, columns inner
visual_rows = len(views) * 256 + 1
```

Each view is independently converted to RGB, stretched to exactly 1024x1024
with Pillow-compatible bicubic interpolation, converted CHW to float, divided by
255, then normalized `(x - 0.5) / 0.5`. Do not preserve aspect ratio, pad, or
insert per-view separators. With trusted `tiles=2`, possible validated layouts
include 257, 769, 1025, and 1281 rows for 1, 3, 4, and 5 views respectively.

For each view, SAM produces `[896,16,16]`; flatten spatial dimensions then
transpose to `[256,896]`. Append 256 learned `query_1024` rows, creating
`[512,896]`, run Qwen, and retain output rows 256 through 511. Apply
`Linear(896,4096) -> exact GELU -> Linear(4096,4096)` independently to every
selected row. Flatten projected views without reordering, then append exactly one
learned `[1,4096]` separator after the final crop. The result is
`[visual_rows,4096]`.

The prompt placeholder `<｜image｜>` is token ID 129279. One placeholder is
expanded to `visual_rows` copies of ID 129279. The receiver batch must carry both
the external 4,096-wide embeddings and those raw IDs: embeddings select hidden
states while IDs remain available to DeepSeek4's HashRouter. Text-only batches
and token-only callers retain existing behavior.

The standard libmtmd helper path owns this bridge. During tokenization, the
DeepEncoderV2 image chunk stores optional route-token metadata loaded from the
mmproj (`129279`); other projector types and audio chunks have no route token.
`mtmd_helper_decode_image_chunk` passes that optional ID to `decode_embd_batch`,
which owns a `std::vector<llama_token>` filled to the chunk's full `n_tokens` and
sets `batch.token` beside `batch.embd`. `decode_embd_batch::get_view(offset,n)`
must set `token = tokens.data() + offset` while slicing embeddings by
`offset * n_mmproj_embd`. It must never allocate a temporary whose lifetime ends
before `llama_decode`. This covers every projected row and the final separator;
non-DeepEncoderV2 callers retain `token=nullptr`. Tests split all four row layouts
at non-divisor `n_batch` values to prove ownership and offsets across subviews.

The route token is persistent chunk state, not transient decode state.
`mtmd_image_tokens` must include the optional ID in `can_batch_with` (chunks with
different or absent IDs cannot batch), `clone`, `mtmd_input_chunk_copy`, and
placeholder creation. Its `serialize`/`deserialize` payload must include the ID
and bump `MTMD_SERIALIZATION_VERSION` from 1 to 2; version-1 payloads are rejected
cleanly rather than restored without routing semantics. Direct save/load tests
and `tools/server/server-common.cpp::server_tokens::{push_back,
push_back_placeholder,serialize,deserialize,clone}` round trips must prove a
restored DeepEncoderV2 chunk still gives every helper subview ID 129279. Batch
merge tests must prove `can_batch_with` prevents route-ID loss or cross-model
mixing.

Existing MTP dual-input behavior is a separate compatibility contract. At the
pin, `llama_context::{encode,decode}` accepts either or both pointers and
`llm_graph_input_embd_h::set_input` uses `embd` as the supplied hidden state while
using `token` for the next-token embedding lookup. DeepSeek4 normal-context visual
batches instead use `embd` as model input and expose `token` only to
`ffn_gate_tid2eid`; they must not alter MTP interpretation. Keep the existing
`llama_batch` layout and `llama_batch_init(n_tokens, embd, n_seq_max)` mutually
exclusive allocation behavior ABI-compatible. The mtmd helper owns its auxiliary
token vector rather than changing that allocator. Add a pinned MTP both-pointer
regression beside DeepSeek4 simultaneous, token-only, and embedding-only tests.

### 4.4 Qwen donor attention mask

For each view, define 512 type IDs as `[0]*256 + [1]*256`. For query row `i` and
key row `j`, additive mask `M(i,j)` is:

```text
0                 if i < 256 and j < 256
0                 if i >= 256 and j < 256
0                 if i >= 256 and 256 <= j <= i
lowest(dtype)     otherwise
```

Thus image rows attend bidirectionally only to image rows. Learned-query rows
attend every image row and causal query rows through themselves. Image rows
cannot attend queries, and a query cannot attend future queries. Apply normal
padding exclusion after this mask. `lowest(dtype)` is the donor Qwen input dtype's
minimum: for the canonical BF16 run it is exactly `-3.3895313892515355e38` when
widened to float32, not pinned llama.cpp's current `-1e9f`. Position IDs are
`0..511` independently for every view; they do not continue across views. Qwen
uses NEOX RoPE, theta 1,000,000, context 131,072, 24 layers, width 896, 14 Q
heads, 2 KV heads, RMS epsilon `1e-6`, SiLU gated FFN width 4,864, and zero
dropout.

## 5. Numerical oracle and golden extraction

Vision-stage goldens are generated from the trusted Python donor and exact BF16
files above, not from a second llama.cpp implementation. Receiver-logit goldens
are generated separately by the pinned DS4 source/patch and both hashed receiver
profiles in Section 1; the Python donor is not a receiver oracle. Vision-oracle
generation uses Python 3.11.15 and the exact root `requirements.txt` lock: NumPy
2.4.6, Pillow 12.3.0, safetensors 0.8.0, PyTorch 2.13.0, and Transformers 4.57.1.
The numerical harness imports the hashed tower module but extracts the
preprocessing/adapter functions from the hashed wrapper without importing vLLM.
vLLM is therefore outside the numerical oracle; any harness that imports the
wrapper must first add the exact vLLM version and distribution hash to a
separately reviewed environment lock.

Every artifact has a JSON manifest recording donor/input/requirements hashes,
all package and Python versions, OS/architecture, device/backend, PyTorch build
configuration, accelerator runtime and driver versions (when applicable),
dimensions, crop boxes, view count/order, dtype, and extraction symbol. Receiver
artifacts additionally record `text-models.json`, DS4 revision and patch hashes,
the Headroom128 or Quality128 target hash, compiler executable/version, effective
compile/link flags, clean build command, executable and Metal source/shader
hashes, receiver profile, context/batch/chunk values, `--metal`,
`--ssd-streaming`, `--ssd-streaming-cache-experts 48GB`, greedy/no-thinking
settings, fixture prompt token IDs (including every repeated 129279), seed,
threading, and full invocation. DSpark paths must be absent. Float comparisons
widen both sides to float32 and apply elementwise
`abs(actual-reference) <= atol + rtol*abs(reference)`. Shapes, row order,
non-finite locations, IDs, crop boxes, and manifest fields are always exact.

Thresholds are declared before implementation and may not be widened after seeing
a failure without a separately reviewed contract change:

| Checkpoint | Extraction point | Acceptance |
| --- | --- | --- |
| Source -> GGUF tensors | raw BF16 payload after inverse loader layout | Exact BF16 bits, `atol=rtol=0`; exact names/shapes/counts |
| Crops/view order/IDs | after `crop_boxes`, placeholder expansion | Exact integers and sequence |
| Decoded/resized pixels | RGB u8 immediately after bicubic resize | Per-channel max difference <= 1 u8 and at least 99.9% of samples exact |
| Normalized pixels | CHW float32 immediately before BF16 cast | `atol=2/255`, `rtol=0`, RMSE <= `0.5/255` |
| SAM | after `net_3`, before flatten, `[V,896,16,16]` | `atol=0.025`, `rtol=0.025`; cosine >= 0.9995 per view |
| Qwen input/mask/positions | concatenated image/query rows, additive mask, and per-view positions | Input `atol=0.025`, `rtol=0.025`; all 512 position IDs and every widened float32 mask value exact (`atol=rtol=0`) |
| Qwen | post-final-RMSNorm selected query rows `[V,256,896]` | `atol=0.05`, `rtol=0.05`; cosine >= 0.999 per view |
| Projector hidden | after `mm.0` and exact GELU | `atol=0.08`, `rtol=0.05`; cosine >= 0.998 |
| Projector output | after `mm.2`, before flatten | `atol=0.08`, `rtol=0.05`; cosine >= 0.998 |
| Separator | appended final row | Exact BF16 source bits after load and exact one-row placement |
| Receiver visual logits | full-vocabulary logits after visual prefill at final visual row and first generated text position | `atol=0.15`, `rtol=0.02`, RMSE <= 0.03, cosine >= 0.999, same argmax |
| Text-only logits | same build/backend/seed before vs after route-token patch, fixed text fixtures | Bit-identical full-vocabulary logits and identical generated token IDs |

CPU is the reference acceptance backend. Metal/CUDA results must satisfy the
same table; a backend needing looser tolerances is unsupported until a reviewed,
backend-specific contract documents evidence. Repeated runs use deterministic
settings (single sequence, fixed seed, no sampling for comparisons).

The minimum fixture set covers: RGB and non-RGB decoding; dimensions immediately
below and at the 1,536-pixel threshold; portrait, landscape, and near-square
images; aspect-ratio ties that exercise the more-crops tiebreak; integer-division
remainders; and the 257/769/1025/1281-row layouts. Fixture image bytes are
committed or fetched by content hash, never generated implicitly at test time.

For each qualifying fixture, extract these named stages:

1. `preprocess.crop_boxes`, ordered source crop rectangles, and `view.rgb_u8` /
   `view.normalized_f32` for global then every row-major crop.
2. `sam.patch_embed`, SAM block outputs 0, 2, 5, 8, and 11, `sam.neck`, and
   `sam.net_3`. Only `sam.net_3` is a release gate; earlier points localize errors.
3. `qwen.concat_input`, per-view position IDs `0..511`, the full `[512,512]`
   additive mask including exact `0`/BF16-min values, Qwen block outputs 0, 11,
   and 23, final norm, and selected query rows.
4. `projector.linear0`, `projector.gelu`, `projector.linear2`, raw separator,
   final flattened `[V*256+1,4096]` output, and the same-length all-129279 route
   vector.
5. Full-vocabulary receiver logits at the two visual checkpoints in the table,
   from each separately pinned Headroom128 and Quality128 DS4 receiver, plus
   text-only prefill and decode logits for fixed ordinary prompts.

Store arrays in an uncompressed or lossless NPZ-compatible artifact and a small
reviewable JSON manifest. CI may fetch large arrays by hash, but hashes and
manifests remain versioned. A mismatch at an earlier stage blocks interpretation
of later-stage results.

## 7. Downstream exit conditions

This contract is satisfied only when downstream work demonstrates all of the
following without silently changing the contract:

- conversion is complete, lossless BF16, provenance-stamped, and rejects the
  wrong separator;
- all four expected row layouts and view order match the donor;
- the Qwen mask is exact and every numerical gate passes at its extraction point;
- a simultaneous IDs-plus-embeddings batch uses embeddings for hidden states and
  IDs only for DeepSeek4 routing;
- text-only/token-only behavior is unchanged;
- `-hf` selects the intended primary, lowercase mmproj, and lowercase DSpark
  sidecars in the packaged directory layout;
- implementation commits remain split along the boundaries above and are
  reviewed against this exact upstream pin.
